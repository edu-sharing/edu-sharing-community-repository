# edu-sharing Frontend-Server

Delivers the edu-sharing Angular app (`Frontend-Server/`, Node/Fastify) and proxies the
backend paths it receives to the repository service. Stateless - a `Deployment`,
scalable via `replicaCount` / `autoscaling`.

## Routing: split between this chart and the repository service chart

Both charts publish Ingresses for the **same hosts** (`ingress.hosts`); nginx picks the
longest matching path:

| Path | Chart | Service port |
|------|-------|--------------|
| `/` (exact) | this chart - the frontend server redirects to the context path | `service.port.api` |
| `/edu-sharing` (prefix, catch-all) | this chart | `service.port.api` |
| `/edu-sharing/rest`, `/eduservlet`, `/login`, `/logout`, `/preview` | repository service chart (`ingress.paths`) | its `service.port.api.external` |

Every other backend path (`/shibboleth`, `/saml2`, `/oauth2`, `/sso`, `/webdav`, ...)
reaches Tomcat through the frontend server, which proxies it
(`Frontend-Server/src/routes/backend-paths.ts`). Sessions are shared via redis, so it
does not matter which repository pod such a request lands on.

## Ports of the repository service

The frontend server talks to the repository service directly, not via the ingress:

* `config.backend.port.external` - everything proxied and the node metadata fetched on
  behalf of the browser. Must be the service chart's `service.port.api.external` (the
  proxy sidecar or the external connector): Tomcat skips 2FA on its internal port.
* `config.backend.port.internal` - the config fetches only (`ValuesBackendInternal`),
  the service chart's `service.port.api.internal`.

## Probes and metrics

On the management port (`service.port.management`): `GET /health/liveness` (never asks
the backend), `GET /health/readiness` (ready once the backend was reached) and
`GET /metrics` (prometheus, `ServiceMonitor` with `global.metrics.servicemonitor.enabled`).
Never exposed through the ingress.

## Istio

Not supported yet: the path split needs a single `VirtualService` for both charts, since
Istio does not order routes across `VirtualService`s of the same host. With
`global.cluster.istio.enabled` the chart refuses to render.
